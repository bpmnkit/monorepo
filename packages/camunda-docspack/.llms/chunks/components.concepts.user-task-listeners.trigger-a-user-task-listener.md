# User task listeners — Trigger a user task listener

The supported user task listener events can be triggered in the following ways.

| Event        | Triggered                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| :----------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `creating`   | When a process instance reaches a user task.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `assigning`  | When the [assign user task API](https://docs.camunda.io/docs/next/apis-tools/orchestration-cluster-api-rest/specifications/assign-user-task.api) is called.When activating a user task that [specifies an `assignee`](https://docs.camunda.io/docs/next/components/modeler/bpmn/user-tasks/user-tasks#assignments) in the process.When a user task is assigned using the [Tasklist interface](https://docs.camunda.io/docs/next/components/tasklist/userguide/managing-tasks#assign-tasks).                                                                                                                                                                                                        |
| `updating`   | When the [update user task API](https://docs.camunda.io/docs/next/apis-tools/orchestration-cluster-api-rest/specifications/update-user-task.api) is called. When the [update element instance variables API](https://docs.camunda.io/docs/next/apis-tools/orchestration-cluster-api-rest/specifications/create-element-instance-variables.api) is called on a user task instance.When the [set variables RPC](https://docs.camunda.io/docs/next/apis-tools/zeebe-api/gateway-service#setvariables-rpc) is called on a user task instance.When variables are set at a user task scope using the [Operate interface](https://docs.camunda.io/docs/next/components/operate/userguide/resolve-incidents-update-variables). |
| `completing` | When a user task is completed using the [Tasklist interface](https://docs.camunda.io/docs/next/components/tasklist/userguide/managing-tasks#complete-a-task).When the [complete user task API](https://docs.camunda.io/docs/next/apis-tools/orchestration-cluster-api-rest/specifications/complete-user-task.api) is called.                                                                                                                                                                                                                                                                                                                                                  |
| `canceling`  | When a canceling process instance terminates a user task.When a [catch event](https://docs.camunda.io/docs/next/components/modeler/bpmn/events) interrupts a user task.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

**Note**
[Process instance modification](https://docs.camunda.io/docs/next/components/concepts/process-instance-modification) does not trigger the `canceling` event. User task listeners are intentionally skipped when a user task is terminated via modification to prevent a failing listener job from blocking the operation.

Once triggered, the workflow engine creates a job that you can process using a job worker.
