# Secrets — Store and create secrets

A reference only resolves to a value once that value is available to the resolving component. How you create and store a secret depends on how you run Camunda 8:

| Deployment model      | Secret storage and management                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| :-------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SaaS**              | The secret store is provisioned and managed for you.Create and update secret values on a cluster's **Cluster secrets** tab.Reference them as `camunda.secrets.<name>`.See [manage connector secrets](https://docs.camunda.io/docs/next/components/hub/organization/manage-clusters/manage-secrets) and the [SaaS-managed secret](https://docs.camunda.io/docs/next/reference/glossary#saas-managed-secret) glossary entry.                                                                                                                                                                               |
| **Self-Managed**      | An operator supplies secret values by configuring a secret store (File, AWS Secrets Manager, or GCP Secret Manager). See [secrets configuration](https://docs.camunda.io/docs/next/self-managed/components/orchestration-cluster/core-settings/configuration/properties#secrets).When deploying with the Helm chart, a [Kubernetes Secret](https://docs.camunda.io/docs/next/reference/glossary#kubernetes-secret) can back the configured store, for example as mounted files for a File store. See [Helm charts secret management](https://docs.camunda.io/docs/next/self-managed/deployment/helm/configure/secret-management).                                        |
| **Local development** | No store configuration is needed. You can manage secrets through `c8ctl` or `c8run` and reference them as `camunda.secrets.<name>`.Manage secrets via `c8ctl` through the `c8ctl cluster secrets` CLI, forwarding to the local development cluster. See [Manage secrets with `c8ctl`](https://docs.camunda.io/docs/next/apis-tools/c8ctl/getting-started#manage-secrets).Manage secrets via `c8run` directly through the `c8run secrets` CLI. See [Manage secrets via `c8run`](https://docs.camunda.io/docs/next/self-managed/quickstart/developer-quickstart/c8run/configuration#manage-local-secrets). |
